# 示例 02 · 模式 D 去 AI 味：一篇典型 AI 稿的体检与改写

**输入**：

原稿是为演示而写的，刻意模仿常见大模型的输出习惯；同题材、同篇幅（344 字 → 317 字）。两份检测报告都由 `tools/ai_flavor_check.py` 直接生成，可以自己复跑：

## 二、体检：先说最致命的两个问题

skill 的规矩是"结构问题 > 表达问题 > 口播问题，结构不过不抠句子"。所以第一刀不是删「值得注意的是」，而是：

1. **没有人在说话**。全文主语是"企业""管理层"，人称密度 2.9 / 千字（口播基准 40.6）。观众听完不知道这跟自己有什么关系。
2. **没有一个具体的东西**。数字 0 个、案例 0 个、场景 0 个。"数据孤岛""组织文化""以点带面"——每句都对，每句都可以原样搬到任何一个行业。

而它看起来的"观点"（「不是技术问题，而是管理问题」）其实是第三个「不是A而是B」，没有让半步，也没有可验证的尺子。

所以改写前先补了一张简版蓝图（完整版见 [示例 01](../01-拆解蓝图-AI如何在企业落地.md)）：

| 蓝图项 | 内容 |
|---|---|
| 定义（≤8 字） | 给 AI 办入职 |
| 大众认知靶 A | "哪家模型最聪明"——有道理（选错会翻车），但片面 |
| 换尺 B | 入职成本：这位"新员工"第一天上班要补齐几样东西 |
| 排除法 | 全员自己用（沉淀不下来）→ 整包外包（翻不准）→ 建大平台（空转） |
| 框架 | 喂资料 · 开权限 · 立验收 |
| 主比喻 | 顶尖实习生第一天上班 |
| 收口（≤12 字） | 三样没给，再聪明也白搭 |

## 三、改写稿

> 如果你是老板，你现在最常问的一句话，大概是：哪家的模型最聪明？
> 这个问题有道理，选错模型确实会翻车。但它非常片面。
> 你想想，一个顶尖的实习生第一天来上班。
> 没账号，没资料，也没人告诉他做完交给谁。他再聪明，能干出活吗？
> AI 进公司，跟这个实习生一模一样。
> 所以 AI 落地，我给它的定义就六个字：给 AI 办入职。
> 那很多人会说，先让全员自己用起来。门槛最低，个人效率也确实马上就上去了。
> 可资料都在个人的对话框里，进不了业务流程，沉淀不下来。
> 还有人说，那整包交给厂商。厂商能写代码，可哪些是例外，哪些是潜规则，都在你业务员的脑子里。他翻不准。
> 那建一个企业级的大平台呢？声势很大，但资料没整理，权限没开，验收没立，平台是空的。
> 所以到底从哪儿开始？就三件事。
> 第一，喂资料，让它读得到。
> 第二，开权限，让它做得了。
> 第三，立验收，让它被验得了。
> 三样没给，再聪明也白搭。

| 在当今数字化转型的时代浪潮下，人工智能正以前所未有的速度重塑各行各业。 | AI 腔开头 + 4 个空词，33 字长句 | 如果你是老板，你现在最常问的一句话，大概是：哪家的模型最聪明？ |

## 五、刻意没做的事

- **没有往稿子里塞「对吧」「其实」**。人称密度 15.8 仍低于口播基准 40.6——这没关系，人味来自"你"和判断，不来自口头禅。
- **没有编数字**。原稿没有数据，改写稿也没有新增任何统计；"六个字""三件事"是结构里的数，不是需要核实的事实。要加真实数据，按蓝图里的 `[用户补充]` 位置补。
